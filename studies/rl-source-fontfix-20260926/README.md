# 强化学习书原文按字形名重抽（替代 mutool 版）

## 问题

这本 PDF 由 macOS Quartz 生成。TeX 数学字体的 `/Differences` 里有正确的字形名（`/pi`、`/alpha`、`/theta`、`/nabla`、`/prime`…），但同时生成的 ToUnicode 表是错的。pdftotext 和 mutool 都按 ToUnicode 取字，所以两者输出同样的错误：

|错误输出|实际字形|例子（旧 → 新）|
|---|---|---|
|`⇡` `✓` `↵` `⌧` `⇢`|π θ α τ ρ|`v⇡(s)` → `vπ(s)`，`✓` → `θ`|
|`↵`（正文字体）|ff 连字|`di↵erent` → `different`|
|`0` `r` `2` `>` `1`（CMSY）|′ ∇ ∈ ⊤ ∞|`s0` → `s′`，`r ln ⇡` → `∇ ln π`，`x>` → `x⊤`|
|`X` `P` `Y`（CMEX）|∑ ∏|`X` → `∑`|
|`"` `@` `!`（CMMI）|ε ∂ ω|`"-greedy` → `ε-greedy`|
|直接丢掉（映射为 U+0000）|− λ γ δ σ β …|`reward is 1` → `reward is −1`|

其中一部分错误字符是字母或数字，按字母数字骨架对齐的 mutool 版（`studies/rl-source-mutool-20260925`）修不了，只补回了被丢掉的符号。

## 做法

1. 按 `/Differences` 里的字形名重写 ToUnicode 表，共 232 类修正，涉及 632 个字体对象。字形名按 Adobe Glyph List 转成 Unicode；TeX 专用名单独列表：大号定界符 → `( [ {`，∑/∏/√，prime → ′，latticetop → ⊤。
2. 对原 PDF 和修正后的 PDF 都运行构图时用的同一命令 `pdftotext -layout`，先按行、再按字符对齐两份输出。
3. 每个冻结段落都能在原输出里原样找到，把它映射到修正后的对应文字：
   - `fontfix_span`：整段换成修正后的文字；
   - `fontfix_patch`：补回的字形让 pdftotext 重新组合了公式行，导致段落边界错位。这类段落保留旧文字和版式，只在对齐位置做已知的字形替换或补回符号；
   - `heading_ff`：标题和位置说明里的 ff 连字。
4. 段落编号、顺序、位置和偏移都不变；D2L（S1）段落不动。

## 校验

- 每段中，不可能由字形修正产生的 ASCII 字母，数量必须和旧文完全相同，脚本不满足就中止。这项检查排除了串段和丢字。修补模式只允许插入非字母数字的符号。
- 四个方法现有的 7 份提交（我们的 1 份，每个基线的质量子集和完整图各 1 份）都通过新原文校验，0 个问题。
- 抽查已知案例：Example 4.1 `reward is −1`，式 10.14 `R̄t+n−1`，`PTD(λ)`、`PQ(λ)`，13.3 节练习 `∇ ln π(a|s, θ)`。
- 事实探针和 QA 题目是从旧原文生成的，带入了同样的错字形。已修正 3 条探针：`rl-fact-ch06-1`（↵→α）、`ch06-2`（A⇤→A∗）、`ch06-3`（⇡→π）；QA 修正 1 条（`rl-qa-ch06-1`）。其余行逐字节不变。rubric 原样复制。

`changes.jsonl` 逐段记录新旧文字，`REBUILD.json` 记录全部 ToUnicode 修正、未映射字形和逐类改动计数。

## 仍未解决

- 约 11 段、36 个错误字形留在排版本来就错乱的公式段里，保守修补对不齐，保持旧文，例如 P000201–P000203 softmax 求导、P001488–P001490、P001899。
- `\vec` 箭头重音（`vector` 字形）原来就被丢掉，仍无对应字符。
- 并排排版和重叠文字层导致的约 250 段版面错位，要修就得重新分段、改段落编号，本次不处理。
- 各方法构图时读到的是旧文本，重评只更新裁判使用的原文。
