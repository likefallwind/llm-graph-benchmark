# D2L 全书图谱：全指标对照表

五个系统跑在同一份语料（`sha256:9b57a1ce…`，1105 chunk）、同一份 benchmark（`d2l-fullbook-v1`）、
同一个检索器（`char-ngram-bm25-v1`，top_k=10）。纵轴为系统，横轴为指标。
判定分三批：v3（2026-08-27，断言三轴 + CaRB 召回）、v2（2026-08-26，其余维度）、
AutoSchemaKG 补测（2026-08-28，同 judge_id 与同 rubric），均由 MiniMax-M3 temperature 0 判定。
**同一格里的数字只能与同一列比较，不同列的 n 与口径都不同。**

## 各列指标的含义

| 指标 | 测什么 | 口径与陷阱 |
|---|---|---|
| **grounding** | 来源证据是否支持该断言陈述的内容 | 只判内容真假，明确要求忽略三元组结构与限定条件 |
| **projection** | (主,谓,宾) 是否忠实投影原文关系：方向、谓词语义与强度、主宾粒度 | prompt 明写「**假设内容本身成立**」。因此对只有共现边的系统会虚高——GraphRAG 68.1% 不代表质量，代表这种关系形式没有投影错误可犯。AutoSchemaKG 抽的是真实语义关系，85.9% 可与 LKG 的 90.4% 直接比较 |
| **scope** | scope 与 text 是否忠实保留原文限定（条件/范围/时间/对象/否定），不丢也不加 | 同样假设内容成立。加限定与丢限定都算 fail |
| **三轴全过** | 同一条断言三轴都 pass（uncertain 计为不过） | 最贴近「可直接下游消费」的读数，也是 F 表的乘数 |
| **CaRB 召回** | 检索到的候选中，是否**存在一条或多条**共同覆盖了该源事实 | 多匹配、噪声不扣分。n=48 分辨力有限：95.8% 与 91.7% 只差 2 条探针，不构成排名 |
| **book_qa** | 24 道全书 QA，答案能否由检索到的图内容支撑 | 受「大图吃亏」偏差影响，量级可能被低估 |
| **entity_admission** | 该实体是否应当被收进图（是不是真概念，而非碎片） | n≈28–30，±15pp。对 AutoSchemaKG 还需先按 entity/event 拆分 population |
| **entity_typing** | 实体类型标注是否正确 | KGGen/GraphRAG 的 `types` 为空，**低分应读作能力缺失而非标注错误**。AutoSchemaKG 见 C 表脚注 † |
| **definition_grounding** | 实体定义是否有证据支撑、不夹带常识补全 | 同上，KGGen/GraphRAG/AutoSchemaKG 的 definition 恒为占位符 |
| **alias_identity** | 别名是否指向同一实体 | 只有 LKG 输出别名层，其余四列没有可评对象 |
| **identity_split** | 同名不同义的实体是否被正确拆开 | `exact` 为 0%、AutoSchemaKG 为 3.7%，都是「不做身份消解」的直接后果 |
| **证据覆盖** | 有多少实体/断言挂得上来源段落 | 只有 GraphRAG 不满（94.8% / 85.1%），其余四行接近或等于 100% |
| **孤立实体率 / 最大连通分量** | 图的连通性 | LKG 连通性最差（32.7% 孤立），是它丢弃不确定边换精度的代价 |
| **表面名重复组** | 规范名字面重复的实体组数 | 直接反映有无身份消解层。LKG 为 0，AutoSchemaKG 有 836 组，为全场最多 |
| **抽取耗时 / token** | 建图成本 | LKG 的数据库时间跨度含失败重试与退避，不能冒充运行耗时，故记 unavailable |

## 怎么读这张表

**五个系统落在四个工作点上，不是同一条曲线上的五个点。**

- **llm-knowledge-graph**：A、C 两块领先，且是唯一有别名、类型、定义、身份层的系统。
  代价写在 D 表：图只有 3,309 条断言，孤立实体率 32.7%——它把不确定的边丢掉了，
  用连通性和覆盖面换精度。B 表显示这个取舍**没有牺牲事实召回**（91.7%，与 AutoSchemaKG 打平）。
- **AutoSchemaKG**：**高召回、低准入**。B 表两项并列第一，说明全书事实确实装进了图里；
  A 表 56.0% 居第二；D 表语义断言 17,826 是 LKG 的 5.4 倍，抽取耗时只有 KGGen 的一半。
  代价全部集中在 C 表：entity_admission 23.3%、identity_split 3.7%、表面名重复 836 组——
  36,942 个节点是靠放宽准入换来的。**适合做召回层，不适合直接当知识库，下游必须自建过滤与消歧。**
- **KGGen `exact`**：D 表规模领先，A 表质量约为 LKG 的六成，相乘后 F 表可消费产出仍是全场最高
  （≈14,900）。C 表整列塌陷是能力缺失，不是标注错误。适合能自建过滤与消歧层的下游。
- **KGGen `semhash`（默认配置）**：与 `exact` 同一批抽取、同一个模型，仅去重方式不同，
  A 表却全线腰斩。根因是英文嵌入语义去重在中文上失效，谓词「等待」占全书断言 50.2%。
  **中文语料不要用默认配置。**（该结论的前提见下方「已知偏差」。）
- **GraphRAG Fast**：E 表快 927 倍且零成本，其余全部不成立——CaRB 召回 0/48，全图只有一种谓词，
  实体是代码 import 片段。它是有意义的地板线，不是质量竞争者。

**读表时的四个陷阱：**
1. C 表中 KGGen/GraphRAG/AutoSchemaKG 的 typing、definition、alias 列测的是「有没有这个字段」，
   不是「标得准不准」。
2. A 表的 projection/scope 列对只有共现边的系统虚高，必须与 grounding 和 uncertain 一起读。
3. B 表 n=48，顶部两名分辨不出高下；不要据此宣称 AutoSchemaKG 召回优于 LKG。
4. D/E 表 AutoSchemaKG 行的原样数字含事件节点与事件边，横比必须换用脚注 ‡ 的对齐口径。

**样本量：** A 表 n=200/系统（±7pp），B 表 n=48 与 24，C 表 n≈19–30（±15pp）。
C 表里 7.1% 与 4.2% 这类差距在统计上区分不开，不应据此排名。

## 已知偏差与未完成项

**AutoSchemaKG（2026-08-28 补测）**

1. **conceptualization 阶段未执行。** 停在 511/42,142 次调用。这是该论文的核心贡献
   （自动 schema 归纳），因此本轮测的是「它的三阶段抽取器」，不是 AutoSchemaKG 全流程。
   C 表的 typing/definition 两格因此不可作为其能力读数。
2. **抽取为双路由混合。** 476 chunk 走官网 `api.minimaxi.com`，629 chunk 走本地 API 网关
   passthrough（同为 minimax-m3），因官网账号中途触及 Token Plan 速率限制与余额下限。
   已按字符归一验证两段产出率一致（16.92 vs 17.49 三元组/千字符，差 3.4%，在噪声内）。
   逐 chunk 归属见 `route-manifest.json`。
3. **4 个 chunk 属误判重跑。** 它们的 API 调用成功并返回合法 `[]`，被当作失败删除后重抽，
   重抽后产出 39/22/15/27 条。原始数据已删除，无法再区分「限流期降级响应」与「普通重摇」。
   影响 4/1105 = 0.36%。重试规则其后收窄为「仅输出无法解析为 JSON 数组时才算失败」，
   因为只对零产出重摇会系统性抬高抽取率。
4. **运行脚本在执行期间被修改**，导致 bash 增量读取错位、脚本尾部未执行，`.finished` 未写、
   评估为手动补跑。抽取数据本身未受影响（分片与汇总在改动前已读入），但
   **该脚本需完整重跑一次才能自证可复现**。
5. **概念化阶段本身不可严格复现**：上游 `concept_generation.py` 用未播种的 `random.sample`
   为实体挑选上下文邻居。

**跨系统**

6. **`llm-knowledge-graph` 的三轴全过率**：本次用统一聚合器复算为 75.0%（150/200），
   与先前发布的 75.4% 相差 0.4pp。该聚合器在其余四个系统上与已发布值精确吻合，
   但 75.4% 对应的分母未能复现。差异不影响任何结论。
7. **KGGen `semhash` 的归因存在未验证前提。** 上游 KGGen 0.4.0 读
   `DeduplicationResult.duplicates`，而其声明依赖 `semhash>=0.3.2` 暴露的是 `filtered`，
   适配层整体替换了 `DeduplicateList.deduplicate` 的方法体来桥接。
   因此「中文语义去重失效」这一归因建立在「替换实现忠实复现了上游行为」这一**未经验证的假设**上。
8. **KGGen `exact` 不是上游提供的模式**，而是本仓库定义的对照组
   （`deduplication_method=None` + 精确字符串并集）。只有 `semhash` 是 KGGen 的默认行为。
   F 表最高的 ≈14,900 来自这个上游不提供的配置。
9. **跨 chunk 聚合为本仓库实现**，未调用上游 `KGGen.aggregate()`（语义基本一致，均为集合并集，
   但需要传递 chunk 级 `unit_ids` 以支撑证据链）。
