# 粗粒度可靠性评测 v1

本协议补充现有 v2.2，不修改历史评分。目的在于展示抽取内容的可靠性与原文可核验性，并把覆盖代价放在旁边阅读。所有方法使用同样的规则，不预设本方法胜出。

## 先判断当前缺口

D2L 已有精度信号：历史 vNext 为 191/200，修正后的 GraphRAG 为 177/200、AutoSchemaKG 语义边子集为 167/200、KGGen 为 146/200。旧48探针分别恢复44、48、45、37条。现有 v2.2 已允许遗漏其他独立事实，不应为突出本方法而再次放宽质量规则。

主要缺口是通用报告将结构统计放在质量之前，以及引用存在率不能表示引用充分性。9月12日两问题试评方向适合，但每方法只有20实体、20断言，且有判定矛盾，不能据此确定高精度系统排名。

因此本轮只调整报告顺序与引用列名，并用更大的固定随机样本检验两个粗粒度问题。不增加条件/方向/粒度等独立得分、加权总分、精度门槛或复杂难例榜单。

## 两个问题，两类对象

| 对象 | 内容正确性 | 引用充分性 |
|---|---|---|
| Entity | 名称所指是否为原文中的有效实体 | 提交原文是否支持该名称所指 |
| 完整 Assertion | 参与者、关系、描述及必要限定整体是否正确 | 提交原文是否支持整条输出 |

正确性标签为 correct / incorrect / uncertain；引用标签为 supported / not_supported / uncertain。错误方向或必要条件改变包含在完整断言判定内，不再对同一条记录另做关系评分。

实体主评测只包含所有方法均提供的名称。定义、类型、别名和全局合并不进入主评分；私有审计保留原始定义及其可用情况，缺省占位文本不当成有效定义。结果不能据此声称实体定义更准确。

断言允许从同条描述读取关系与限定，不要求专用 scope 字段。弱关系词不自动判错；明确错误的端点或谓词不能由正确描述修复。不要求单条断言覆盖所在段落的其他独立事实。各方法原生记录的信息量不同仍是测量边界，不通过拆碎输出或奖励谓词数量解决。

## 分开判定内容与引用

每条记录发起两次独立调用：

1. 内容裁判只看 target 和 reference_context。参考上下文采用原提交父段落及每段前后一个相邻段落，所有方法同规则。
2. 引用裁判只看 target 和 submitted_sources，不接收相邻段落或内容裁判结果。

提交引用按去重后的原始 unit_id 解析真实原文；不裁剪长证据，不替系统寻找短句，不使用未经逐字核验的 model quote 替换真实段落。引用缺失为 not_supported；长引用不自动判错。无法读取的来源或实际歧义保留 uncertain。

内容上下文仍由原引用定位，因此这是局部来源核验，不是独立全书金标。书中别处存在支持时，局部缺失只能判 uncertain，不能自动判 incorrect。引用长度仅在充分支持的记录上作附录描述；不同方法抽到的事实不同，不能据此声称同事实查证效率提升若干倍。

## 抽样与冻结

- 沿用四种已经完成的历史提交：本方法 vNext、GraphRAG 中文 standard、KGGen LM_BASED、AutoSchemaKG 既定 semantic track。
- AutoSchemaKG 沿用剔除 `is participated by` 的既定评测范围，不称全部原生边质量；GraphRAG 的关系描述正常参与评测。
- 固定种子 20260920，每方法100实体、200断言，共1200条记录、2400次主判定。关系与 Assertion 不重复计作独立样本。
- 排除 sampling.json 列明历史材料中可识别的已评项目和已展示候选；记录排除方法、总体、可抽样数和最终样本。已见记录的排除意味着结果针对剩余可抽样输出，不能无条件外推全图。
- 一次抽样后冻结全部任务、私有映射、提示、开发题、运行代码、协议和输入哈希。不因错误率高、长证据、调用失败或审核拒绝而替换样本。
- 公开调用只含对象种类、目标和来源，不含方法名、历史标签或私有映射。输出风格仍可能透露方法，盲化不是完全保证。

## 结果与覆盖代价

主表只列实体所指正确、实体引用充分、完整断言正确、断言引用充分；同时提供 correct/incorrect/uncertain、supported/not_supported/uncertain、技术缺失与固定样本分母。

主表的通过/全样本是已确认比例，未完成时不是最终准确率。另列明确判定上的通过率与Wilson区间；不确定、错误或缺失不从报告消失。二项区间不覆盖同段相关性、裁判偏差或跨书泛化。

旧48个来源探针的恢复率单独作为历史参考，不重新打分，不称全书召回，不与本轮精度拼F1。图规模和成本不是质量替代项。本轮不重新构图，模型调用费用是评测费用，不能冒充算法构图成本。

全部方法同时报告，不按是否符合优势假设选择结论。若精度差距缩小、引用支持率接近或不确定很多，应照实说明；同模型判定仍需独立复核，不能作为人工金标或SOTA结论。

## 运行约束

固定官方 MiniMax-M3 与 `https://api.minimaxi.com/v1/text/chatcompletion_v2`。只继承 MINIMAX_API_KEY，不把密钥写入命令、日志或快照。

一个后台进程服务全部方法、两种判定和重试，6个worker与共享6个HTTP文件锁槽位。只对调用失败或格式无效做有界重试，不因有效标签不合预期而重试。计费/认证等终止错误停止补充队列；原始响应、每次尝试、实际HTTP峰值、使用量和完成状态留存。

先执行六条通用开发检查、共12个判断；这只检查基本语义与接口，不是独立裁判校准。未通过时保留结果并停止，不能自动改规则到满分。后台入口保存 .started、run.log、progress.json 和 .exit；仅所有主判断有效且退出0时写 .finished。

## 显式探索模式

用户随后继续确认“同意，发送吧”。本轮以 `--exploratory` 冻结新的探索性运行，保留原评分提示、原1200条正式样本及失败开发检查，不通过再次调规则获得通过。该模式只收集描述性模型判断，报告首部必须突出裁判未通过开发检查，summary 独立记录 judge_validation；技术上的2400/2400完成不表示裁判准确率已经验证，也不能用于可靠排名。

默认模式仍在开发检查失败后停止。探索模式不豁免数据发送审批、凭证保护、共享6并发或提供方终止错误停队列。为避免无意义地重跑已知开发检查，可以在逐字核对提示与开发题一致后复用原12个结果，保留来源与哈希；不能复用不同题目或不同提示的标签。
